# Публичные сведения об Arena Agent Mode и применение в ZI-Orkas

Проверено 18 ноября 2026 года. Ниже — только сведения из публичных материалов Arena, а не описание закрытой внутренней реализации или API. Наличие моделей в Arena не означает, что их API бесплатны или доступны приложению ZI-Orkas.

## Что сообщает Arena

- [Инструкция Agent Mode](https://help.arena.ai/articles/5432423882-how-to-use-agent-mode): при начале сессии выбирается модель-оркестратор из моделей лидерборда; она решает, какие инструменты вызвать. В документе сказано, что выбор случайный для измерений и модель обычно сохраняется на протяжении беседы; при риске сбоя возможна замена. Перечень, цены, лицензии и прямые API всех поставщиков этот документ не устанавливает.
- [Объявление Agent Mode](https://arena.ai/blog/agent-mode): среда предоставляет инструменты поиска, файлов, программирования и sandbox/bash. Агент выполняет многошаговую задачу, а не просто генерирует один ответ.
- [Коннекторы Agent Mode](https://arena.ai/blog/connectors-in-agent-mode): подключение через OAuth, пользователь включает сервис для конкретного хода; агент загружает только необходимые определения инструментов. Это описание продукта Arena, а не подтверждение готовности Gmail/Telegram в ZI-Orkas.
- [GitHub workflow в Agent Mode](https://arena.ai/blog/coding-in-agent-mode): описаны чтение и изменение файлов, команды, репозиторий и видимый diff.
- [Agent Arena 2024](https://arena.ai/blog/agent-arena-2024): старый отдельный эксперимент описывает комбинации моделей, инструментов и фреймворков (включая LangChain, LlamaIndex и CrewAI). Его нельзя принимать за доказательство внутренней архитектуры текущего Agent Mode.

## Реализовано в этом изменении ZI-Orkas

- Встроенные роли AndroidDeveloper, WindowsDeveloper, BuildAgent, DiagnosticsAgent и ArenaHandoff используют существующий механизм агентов и выбранного пользователем провайдера. Это инструкции и наборы инструментов, не самостоятельные модели и не гарантия бесплатного облачного доступа. Делегирование и результат зависят от оркестратора и среды.
- При ранжировании успешной потоковой модели используется время до первого события вывода, а не продолжительность всего ответа. При чередовании сетей нельзя перескочить на узел в cooldown или сильно худший по общему баллу. Локальные модели сохраняют свой приоритет. Нет параллельной отправки запроса нескольким поставщикам.
- В существующий локальный журнал добавлены длительность и время до первого события, номер попытки, признак локального узла и хэш идентификатора узла, без текста запроса или ответа. Это не полноценное отображение этапов в интерфейсе; первый вывод может быть внутренним reasoning, а не видимым текстом. Хэши нужны лишь для сопоставления и не являются именем провайдера. Перезапуск сбрасывает данные здоровья.
- Проверки — локальные автоматические тесты с имитированными поставщиками, не измерение скорости реальных сервисов и не доказательство ускорения на устройстве пользователя.

## Что остаётся

Отдельная пользовательская панель этапов с безопасным указанием выбранного провайдера; бюджет и отмена повторов на уровне всей задачи; согласие при смене внешнего получателя данных; дополнительные проверенные провайдеры с прозрачными условиями; интеграционные проверки агентов и OAuth с реальными сервисами. Gmail/IMAP и Telegram не реализованы этим изменением. Не включать сторонние модели на основании неподтверждённых утверждений о бесплатности или доступности и не отправлять приватные данные новым поставщикам без согласия пользователя.

Ручная передача задач между ZI-Orkas и Arena описана в `docs/arena-manual-handoff.md`. Автоматического коннектора к Arena нет; публичные условия Arena ограничивают автоматизированный доступ.
